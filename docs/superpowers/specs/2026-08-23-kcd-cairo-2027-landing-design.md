# KCD Cairo 2027 — Coming Soon Landing Page

**Date:** 2026-08-23
**Status:** Approved for implementation
**Repo:** `cloudcommunitylabs/kcd-cairo`

## Problem

This repo is a fork of the OCP Global Summit event site. It is built on the
`@openeventkit/event-site` Gatsby theme (v2.1.62) and all of its content still
belongs to OCP — San Jose Convention Center, OCP ticket pricing,
`opencompute.org` links.

It does not build. The theme's `gatsby-node.js` runs `onPreBootstrap`
unconditionally, fetching marketing settings, summit, events, speakers and
sponsors from FNTech's OpenEvent API using an OAuth client-credentials grant:

```
ValidationError: Invalid options provided to simple-oauth2 "auth.tokenHost" is required
  - gatsby-node.js:257  Object.exports.onPreBootstrap
not finished onPreBootstrap - 0.162s
error Command failed with exit code 1
```

Verified by running `yarn build` at commit `b3fc9c6` with a clean
`yarn install --frozen-lockfile`. Without FNTech credentials and a registered
summit ID, no page renders. Hiding individual sections inside the theme is
therefore not possible — the failure happens before any page is created.

## Goal

Ship a KCD Cairo 2027 coming-soon landing page, deployed to Cloudflare Pages by
the same mechanism `cloudcommunitylabs/kcd-new-york` uses, without deleting any
part of the existing template.

## Non-goals

- Configuring the openeventkit theme against a real OpenEvent backend.
- Porting OCP's content pages (registration, travel, FAQ) to Cairo.
- Schedule, speakers, sponsors, registration or CFP functionality.

## Approach

A minimal self-contained landing page. The theme plugin is commented out of
`gatsby-config.js`; every template file stays on disk untouched.

Two alternatives were considered and rejected:

- **Obtain FNTech credentials first.** Correct long-term, but blocks shipping on
  a third party.
- **Patch `onPreBootstrap` via patch-package.** Needs no credentials and keeps
  theme components rendering, but summit data would still be empty, and this
  repo bumps the theme often (2.1.55 → 2.1.62 in recent history), so the patch
  would break repeatedly.

### The reversibility contract

Nothing is deleted.

- `@openeventkit/event-site` stays in `package.json` and `yarn.lock`.
- `src/content/**`, `src/pages/content-pages/**`, `src/images/**`,
  `static/img/**`, `netlify.toml` are untouched.
- `gatsby-config.js` keeps the theme entry in a commented block that states why
  it is off and what is required to switch it back on.

Restoring the theme is: uncomment one line **and** supply the FNTech env vars
listed in `node_modules/@openeventkit/event-site/env.template`. The uncomment
alone will not build.

### Why the OCP pages go dormant

Gatsby's default page creation only picks up `.js/.jsx/.ts/.tsx` under
`src/pages`. The OCP content pages are `.md` and depend on the theme's
`gatsby-plugin-mdx` to become routes. With the theme off they produce no routes
while remaining on disk. This is the mechanism that "hides what isn't ready" —
no file is edited to achieve it.

## Components

### `package.json` — explicit React

`react` and `react-dom` are added as direct dependencies, pinned to the `18.2.0`
already resolved in `yarn.lock`. Today they resolve only as transitive
dependencies of the theme; once the theme is out of the plugin list, a page that
imports React must declare it. `@openeventkit/event-site` and `gatsby` entries
are unchanged.

`yarn.lock` is regenerated by a plain `yarn install` and committed, because CI
runs `--frozen-lockfile` and a stale lockfile would fail only there.

### `src/content/event-data.json` — single source of content

Mirrors the `event-data.json` convention already used in `kcd-new-york`, so
anyone who has worked on that repo recognises it.

```json
{
  "name": "Kubernetes Community Days Cairo 2027",
  "shortName": "KCD Cairo 2027",
  "city": "Cairo",
  "country": "Egypt",
  "year": "2027",
  "dateLabel": "Date to be announced",
  "siteUrl": "https://kcdcairo.com",
  "links": {
    "linkedin": "",
    "x": "",
    "contactEmail": "",
    "newsletter": ""
  },
  "program": {
    "kcd": "https://kubernetescommunitydays.org/",
    "cncf": "https://www.cncf.io/"
  }
}
```

**Visibility is derived from the values, not from a separate flag block.** A CTA
renders if and only if its string is non-empty. This deliberately differs from
`kcd-new-york`, which carries an explicit `features` object — a flag and a value
can contradict each other, and on a page with three optional CTAs the flags earn
nothing. Consequence: the page is safe to ship with blanks, and filling a CTA
later is a one-file edit with no code change.

All four `links` values are literal strings used verbatim:

- `linkedin`, `x` — full profile URLs, not handles.
- `contactEmail` — a bare address; the page prefixes `mailto:`.
- `newsletter` — a URL (Google Form, Mailchimp hosted page, Buttondown page),
  not an API endpoint. It renders as a link, so no form handler, no CORS, no
  secret.

### `src/pages/index.js` — the page

Sections, top to bottom:

1. Official CNCF KCD horizontal mark.
2. `city` set large, `year` treated as a distinct element.
3. "Coming {year}" plus `dateLabel`.
4. CTA row — LinkedIn, X, email, newsletter; each conditional on its value.
5. Footer — ties the event to the CNCF KCD program, links `program.kcd` and
   `program.cncf`, shows the current year.

Uses Gatsby's Head API for `<title>`, meta description, canonical URL from
`siteUrl`, Open Graph and Twitter card tags, and an SVG favicon link. No
`gatsby-plugin-manifest` — it would need a ≥512px PNG and a plugin for one tag.

### `src/pages/index.css` — styles

Plain CSS, no framework. Deep near-black ground `#0B1016`; Kubernetes blue
`#326CE5` as the anchor; a warm sand accent `#E0A458` for Egypt without pyramid
clip-art. A low-opacity Islamic geometric tiling motif as inline SVG in the
hero — the one distinctive element, and it needs no image asset.

These three values are the starting point, not a contract; the implementer may
adjust them to satisfy the contrast requirement below, and the final values are
recorded in the CSS.

Requirements: responsive from 320px up, `prefers-reduced-motion` respected on
any transition, and text/background contrast meeting WCAG AA (4.5:1 body,
3:1 large text). Contrast is checked against the final values, not assumed.

### `src/images/kcd-logo-color.svg` — brand mark

The official mark from
`cncf/artwork/other/kubernetes-community-days/horizontal/color/kcd-logo-color.svg`.
CNCF artwork is CC-BY 4.0 and KCD organisers are its intended users. Committed
to the repo rather than hotlinked, so the build has no network dependency.

### `static/CNAME` — `kcdcairo.com`

Matches `kcd-new-york`'s `static/CNAME`. Cloudflare Pages takes custom domains
from project settings rather than this file, so it is documentation of intent
and parity with the sibling repo; the custom domain must still be added in the
Cloudflare dashboard.

### `.github/workflows/deploy.yml` — Cloudflare Pages

Ported from `kcd-new-york/.github/workflows/deploy.yml`.

- Triggers: `push` to `main`, `pull_request` to `main`, `workflow_dispatch`.
- `permissions: contents: read`, `pull-requests: write`.
- Node from `.nvmrc` (20.19.4), yarn cache, `yarn install --frozen-lockfile`.
- `yarn build`.
- `cloudflare/wrangler-action@v3` running
  `pages deploy public --project-name=kcd-cairo-2027 --branch=${{ github.head_ref || github.ref_name }}`.
- On pull requests, upsert a single preview-URL comment (find-existing-then-update,
  so reruns do not spam the thread).

The PR comment body is rewritten for Cairo. NY's version hardcodes a review
checklist about floor plans, transit tabs and a photo gallery that do not exist
here; copying it verbatim would be actively misleading.

### `README.md`

Currently the stock Gatsby minimal-starter readme — it describes neither this
repo nor this event. Replaced with: what the site is, how to run it, where
content lives, how deployment works, and an explicit section on the parked
theme and what re-enabling requires.

## Prerequisites outside this repo

The deploy step fails without both. Neither can be done from the codebase.

1. A Cloudflare Pages project named `kcd-cairo-2027` must exist.
   `wrangler pages deploy` does not create projects non-interactively.
2. Repo secrets `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`.

The build and the page are verifiable locally regardless, so the PR is
reviewable before these land.

## Error handling

The page has no runtime data fetching, no forms and no client-side state, so it
has no runtime failure modes to handle. The failure modes are build-time:

- **Missing `event-data.json` key** — the page reads nested values via optional
  chaining and renders nothing for a missing CTA rather than crashing the build.
- **Theme accidentally re-enabled without env vars** — build fails loudly at
  `onPreBootstrap`, which is the correct behaviour and is documented in
  `README.md` and in the `gatsby-config.js` comment.

## Verification

Evidence required before the PR is opened, in this order:

1. `yarn build` exits 0.
2. `public/index.html` exists and contains the literal strings `Cairo`, `2027`
   and the `dateLabel` — confirming real content rendered, not an empty shell.
3. The built route list contains `/` and no `registration`, `travel` or `faq`
   routes — confirming the OCP pages are dormant.
4. The build log contains no request to any FNTech or OpenEvent host, and no
   `onPreBootstrap` entry — confirming the theme is genuinely out of the graph.
5. Every non-empty URL in `event-data.json` resolves (HTTP 2xx/3xx). Empty
   values are skipped.
6. `yarn install --frozen-lockfile` succeeds against the committed `yarn.lock`
   after `package.json` gains `react`/`react-dom` — CI uses this exact command,
   so a stale lockfile would only surface in CI.

No claim of completion is made on a green exit code alone.

## Out of scope, worth a follow-up

- Populating the CTA values in `event-data.json`.
- Adding the custom domain to the Cloudflare Pages project.
- A branded `src/pages/404.js`. Without it Gatsby emits no `404.html` and
  Cloudflare Pages serves its own generic 404. Acceptable for a one-page holding
  site; worth adding when the site grows past one route.
- Deciding whether Cairo continues with the openeventkit theme or moves to a
  custom Gatsby site as `kcd-new-york` did. Recorded here because the answer
  determines whether the parked theme is ever revived; it does not block this
  page.
